# Gotchas

- **SimpleWebAuthn бросает исключение на неверный ответ**, а не возвращает `verified: false`. Без обёртки
  `verified()` в `routes/auth.ts` чужой origin или подделанная подпись давали 500.
- **POST без тела с `content-type: application/json` — 400 у Fastify.** Фронт всегда шлёт `{}` (`api.ts`).
- **TypeScript 7 не ставить**, пока vue-tsc не умеет нативный компилятор: 7.x — порт на Go без прежнего JS API.
- **better-sqlite3 собирается из исходников** (node-gyp): в builder-образе нужны `python3 make g++`.
- **X-Forwarded-For в nginx передаётся как есть** (`$http_x_forwarded_for`): Caddy уже записал туда адрес
  клиента. `$proxy_add_x_forwarded_for` добавил бы адрес Caddy, и лимит частоты на вход считал бы всех
  одним клиентом.
- **Токен инвайта в БД — хэш.** Ссылку видно один раз при создании; потерял — создать новую.
- **Принятый инвайт заменяет права от владельца целиком**, а не добавляет к ним.
- **`DEV_LOGIN=1` работает только без `NODE_ENV=production`** — в образе api вход по имени выключен всегда.
- **На сервере `docker compose` — всегда с `-f deploy/docker-compose.yml`** из каталога установки:
  compose-файл лежит не в корне. **`up` — ещё и с оверлеем доступа**, иначе web отключится от прокси.
- `networks:` без `default` отрезает web от api. Если фаервол ограничивает частоту SSH, скрипты держат ≤3 подключения.
- **Первый деплой на новый поддомен: Caddy выпускает сертификат дольше минуты.** Проверка в
  `deploy.sh` ждёт до ~5 минут; `000` от curl в первые минуты — это ещё нет сертификата, а не падение.
- **Смена месяца для плана считается по `TZ` контейнера api.** Без неё контейнер живёт в UTC, и правка плана в
  первые часы нового месяца по местному времени изменит план прошлого.
- **better-sqlite3 не понимает нумерованные параметры `?1`** — `RangeError: Too many parameter values`.
  Повтор одного значения — только именованными (`@owner` и объект в `.all({ owner })`).
- **EventSource навсегда закрывается на ответ-ошибку** (502 от nginx, пока api перезапускается при
  деплое) — сам переподключается только после сетевого обрыва. Свой таймер — в `stores/shopping.ts`.
- **SSE-комментарии (`: ping`) клиенту не видны**, поэтому пинг — обычное событие `{"type":"ping"}`:
  по нему сторож отличает живое соединение от полуоткрытого (прокси держит сокет, сервера за ним нет).
- **Открытые SSE-потоки держат `app.close()`.** Без хука `preClose` → `bus.closeAll()` остановка api
  ждала их, и `docker stop` убивал процесс по таймауту 10 с.
- **iOS держит PWA в памяти и почти не перезагружает её.** Service worker ставит новую версию в фоне,
  а на экране остаётся старая. Поэтому `src/pwa.ts` проверяет обновление при каждом возврате на экран
  и раз в 30 минут и перезагружает страницу, когда новая версия взяла управление (не посреди ввода).
- **`injectRegister: false` выключает в vite-plugin-pwa `skipWaiting`/`clientsClaim`** — плагин ставит их сам
  только при `injectRegister: 'auto'`. Без явных `workbox.skipWaiting/clientsClaim` новая версия
  остаётся `waiting` навсегда. Проверено на `vite preview`: сборка test3 → test4, `reg.update()` → перезагрузка.
- **vite-plugin-pwa ждёт `workbox-window` в зависимостях** для `virtual:pwa-register` — без него падает сборка.
- **`lower()` и `LIKE` в SQLite регистронезависимы только для латиницы.** «Коммуналка» и «коммуналка» для
  них разные. Сравнение названий — в JS через `historyKey()` (нижний регистр, «ё» → «е»).
- **`types { … }` в nginx ЗАМЕНЯЕТ всю таблицу MIME-типов, а не дополняет её.** Блок
  `types { application/manifest+json webmanifest; }` на уровне server отдал всё остальное как
  `application/octet-stream`: Safari предлагал скачать страницу, а `sw.js` не как JavaScript отвергал —
  установленное приложение перестало обновляться. Тип для одного файла — только в его `location`
  (`types { }` + `default_type`). `deploy.sh` теперь проверяет типы `/`, `/sw.js`, manifest и бандла.
- **Safari на iPhone может «застрять» на старой сборке PWA.** (Скорее всего, следствие пункта выше.) При каждом
  запуске телефон запрашивал `/sw.js` (200) и дальше ничего — ни `workbox-*.js`, ни `/assets/...`, то есть новый
  service worker даже не начинал ставиться, а у старой сборки нет своей логики обновления.
  Лекарство со стороны сервера: фронт шлёт ревизию в заголовке `x-app-revision`; `GET /api/me` без него
  получает `Clear-Site-Data: "cache", "storage"` (Safari 17+) — браузер снимает service worker и кэш,
  следующий запуск грузит свежую сборку из сети. Cookie не трогаются. Диагностика — `docker logs money-web-1`
  по User-Agent iPhone: есть ли запросы к `/assets/` после `/sw.js`.
- **Заголовок `Clear-Site-Data` не виден из JS** (`fetch().headers.get` → null) — проверять curl.
- В «Ещё» — версия приложения и сервера (`/api/health` отдаёт `revision`) и «Обновить принудительно»
  (снять service worker, стереть Cache API, перезагрузиться; localStorage и сессия остаются).
- **Поля ввода мельче 16 px — Safari на iPhone увеличивает страницу при фокусе.** Основной шрифт 15 px,
  поэтому в `base.css` у `input/select/textarea` — `font-size: max(16px, 1em)`.
- **Миграция может быть функцией** (`MIGRATIONS` в `db/migrations.ts`): когда данные надо пересчитать в JS —
  например, ключи названий (`nameKey`), которые SQLite для кириллицы не посчитает.
- **Перед `click` всегда приходит `mouseenter` — и на iPhone тоже.** Обработчик «нажал ещё раз — скрыть»
  гасит подсказку сразу после показа (график сводки). Нажатие должно выбирать, а не переключать.
- **`.btn.plain` перебивает цвет из scoped-стилей страницы** (одинаковая специфичность, base.css грузится
  позже) — для красных кнопок есть `.btn.plain.danger` в base.css.
- **Удалённая категория не забирает траты с собой.** Если удалить «Авто» и завести новую с тем же именем, старые
  траты остаются на архивной и в факт новой не попадают. Переименовывать, а не пересоздавать; массово — `cli recategorize`.
